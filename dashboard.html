HACOO BOT V6 — contrôle IA

Vérifie les fournisseurs API configurés et enregistre des propositions d’amélioration. Les tests API envoient une requête courte et peuvent consommer du quota.

Chargement de l’état V6…

IA autonome — centre de pilotage

L’IA observe les statistiques agrégées, propose des améliorations et génère des candidats isolés. Le déploiement autonome à faible risque est préparé derrière une allowlist stricte et reste désactivé par défaut.

Chargement du cycle autonome…

Centre de pilotage autonome

Une vue centralisée des décisions, diagnostics, conversations et commandes de contrôle. Les actions réellement exécutées sont journalisées; le chat seul ne peut pas modifier le code ni déployer.

DÉCISIONS

Pourquoi l’IA agit

Chaque cycle, proposition, blocage ou tentative de déploiement apparaît dans le journal avec son horodatage et ses détails disponibles.

Agent de développement autonome

Crée une tâche persistante : l’IA lit un module, génère une version candidate, vérifie la syntaxe et les règles statiques. Le déploiement n’est tenté que si l’allowlist, GitHub, les tests et le contrôle runtime sont configurés. La production n’est jamais remplacée par un simple chat.

Chargement de l’agent d’ingénierie…
Aucune tâche de développement.

Parler à l’IA autonome

Demande-lui d’expliquer une décision, d’analyser un incident ou de proposer une amélioration. Une réponse du chat ne vaut pas autorisation de déploiement.

Conversation vide. Pose une question à l’IA.
L’appel utilise le fournisseur IA configuré et peut consommer du quota.

Journal complet des décisions récentes

Les événements les plus récents apparaissent en premier. Les secrets ne doivent jamais être saisis dans le chat.

Chargement du journal…
01 · Fonctionnement

Revue périodique

À chaque cycle, l’IA examine les compteurs du bot (file, erreurs, doublons, modération) et prépare une seule proposition prudente.

Réglages FadeHost : V6_AUTONOMY_ENABLED et V6_AUTONOMY_INTERVAL_MINUTES.
02 · Limites

Plafond et consommation

Un plafond quotidien évite les cycles sans fin. Les appels IA peuvent consommer le quota du fournisseur configuré.

Réglage FadeHost : V6_AUTONOMY_MAX_RUNS_PER_DAY. Valeur par défaut : 4 cycles/jour.
03 · Fichiers candidats

Proposition isolée

Si cette option est activée, l’IA peut générer un module candidat séparé. La génération seule ne lance pas le candidat. Si un déploiement protégé est configuré, les tests de pré-déploiement l’exécutent dans une copie temporaire avec un environnement épuré; ce n’est pas un sandbox système.

Réglage FadeHost : V6_AUTONOMY_GENERATE_CANDIDATES.
04 · Niveau 3 protégé

Déploiement sûr sur allowlist

Seuls des modules auxiliaires explicitement autorisés peuvent passer la porte automatique. Les fichiers critiques, secrets, données, tableau de bord et dépendances sont exclus.

Le push GitHub ne confirme pas que FadeHost a redémarré. Le mode reste désactivé par défaut; si le contrôle HTTPS runtime échoue, le système tente de repousser la version précédente, puis il faut vérifier le redémarrage FadeHost.

Fournisseurs IA configurés

La présence d’une clé indique qu’elle est configurée, pas que l’API fonctionne. Utilise le test ci-dessous pour vérifier la connexion; ce test peut consommer du quota.

Laboratoire d’amélioration

Enregistre une proposition manuelle ou génère un candidat isolé. Les actions de cette zone ne changent pas le code de production.

Générer un module candidat

Le code généré est sauvegardé dans workspace/candidates, contrôlé syntaxiquement et jamais exécuté ou déployé par ce bouton.

Commandes en langage naturel

Les commandes sont limitées à une liste d’actions autorisées. Le système ne lance pas de commandes shell et ne modifie pas les protections à partir d’une demande libre.


      
Optimisation éditoriale
L’IA propose une version plus claire. La proposition n’est jamais publiée automatiquement et doit être relue.

      

      
Publications programmées
Le texte passe un contrôle qualité avant programmation. Si le résultat d’un envoi est incertain après une panne, HACOO ne le renvoie pas automatiquement afin d’éviter un doublon.

      

        

        

        

      

      

      

      
Mémoire explicable
Conserve uniquement les règles ou préférences explicitement ajoutées par l’administrateur, avec leur justification. N’y colle pas de secrets.

      

      

      
Déploiement protégé FadeHost
Le candidat est testé dans une copie temporaire avec un environnement épuré (ce n’est pas une sandbox système), puis poussé sur la branche GitHub configurée. FadeHost ne le déploie que si cette application suit cette branche. Commence par une branche de staging, pas par la production.
